- `code.primitives` =
  | Call shape | Reach for | In-repo helper | Reason the wrapper exists |
  |---|---|---|---|
  | Put a caller-supplied value into a command string | writing `"$value"` into the string | `shell_quote_arg` (`templates/mcp-shared/environment.sh`) | Guarantees one shell parse yields the original literal. Double quotes, not single: the docker, docker-compose, and vagrant wrappers embed the whole command inside a single-quoted string, so a single quote in generated output terminates it. |
  | Accept a caller path or pattern at all | using it as given | `assert_no_shell_hostile_chars` (`environment.sh`) | Refuses single quotes and line breaks, which no fixed escaping depth survives across every wrapper. Rejecting is correct for a path. |
  | Read a `paths` argument from tool JSON | `jq -r '.[]'` then joining | `parse_paths_json` (`environment.sh`) | Distinguishes absent from malformed.   | Decide a supplied path is a usable target | trusting the tool's exit code | `assert_paths_exist`, `assert_paths_lintable` (`environment.sh`) | Lint scripts carrying `--no-error-on-unmatched-pattern` lint nothing and still exit 0.   | Read one value out of the loaded config | `jq -r "$path" "$LINT_CONFIG_FILE"` | `_get_config_value` (`environment.sh`) | An absent config file yields the supplied default instead of a jq error on stderr. |

  | Read a JSON file the server owns | `cat "$file"` | `read_json_file` (`templates/mcp-shared/mcpserver_core.sh`) | A missing file logs an ERROR and yields `{}` rather than emitting nothing into a `jq` pipeline. |

- `code.di_pattern` = The outermost injection is `plugins/<plugin>/.mcp.json`, which points each server name at `${CLAUDE_PLUGIN_ROOT}/mcp-server-*/server.sh`; `${CLAUDE_PLUGIN_ROOT}` is the one value supplied from outside the repository. Below it, a bash MCP server's composition root is `plugins/<plugin>/mcp-server-*/server.sh`: it sets and exports the module inputs (`MCP_CONFIG_FILE`, `MCP_TOOLS_LIST_FILE`, `MCP_LOG_FILE`, `PROJECT_ROOT`, `CONFIG_PREFIX`), then sources the shared modules in dependency order and calls `run_mcp_server`. A sourced module reads its inputs from those exported variables and takes everything else as positional parameters; it never discovers its own configuration. Hook scripts take their input as JSON on stdin via `parse_hook_input`. Python uses parameter injection (`Path` arguments), never module-level state.
- `code.export_conventions` = A leading `_` marks a sourced module's internal function or variable (`_merge_configs`, `_discover_configs`, `_FOUND_CONFIGS`); unprefixed names are that file's public API. A sourced module that has a non-obvious public surface states it in a `# Public:` header block listing each exported function with a one-line contract, as `plugins/dev-tooling/shared/scope.sh` does — write one when adding a module other files will source, and keep it current when the surface changes. Python mirrors the underscore rule: `__init__.py` declares `__all__` and re-exports the public surface from `core.py`; `_`-prefixed names stay private, including in the standalone `lsp_proxy.py`, which has no package boundary and so no `__all__`.

  An MCP tool is exported by doing **both**: defining `tool_<name>` in a sourced lib, and adding its entry with an `inputSchema` to the server's `tools.json`. `handle_tools_call` dispatches via `type "tool_${tool_name}"` and `validate_tool_arguments` validates the call against that entry. A function without its `tools.json` entry is unreachable; an entry without an `inputSchema` is dispatched unvalidated.
- `code.footgun_additions` =
  - An MCP server's **stdout is the JSON-RPC stream** — `run_mcp_server` writes each response to it. A stray `echo` or `printf` to stdout from any sourced module corrupts the protocol. Diagnostics go through `log` to the log file; a tool's payload is returned from its `tool_*` function.
  - A tool function's output is captured as `output=$("$func_name" "$arguments" 2>&1)`. Its stderr is **merged into the result the client sees**, not discarded — anything written there becomes part of the tool response.
  - Two ShellCheck configs are in force. Root `.shellcheckrc` disables SC1091 repository-wide, so a wrong `source` path is never caught by lint and surfaces only at runtime, where `set -euo pipefail` turns it into a hard exit — verify a new `source` path by reading it. `plugin-tests/.shellcheckrc` additionally disables SC2034, SC2329, SC2030, and SC2031 for test files, so an unused variable or a lost subshell mutation in a test is silent too.
  - CI runs ShellCheck over `.bats` and `.bash` files as well as `.sh`, across `plugins`, `plugin-tests`, and `.github/scripts`. A test helper is linted on the same terms as a server.
  - `shopt -s inherit_errexit` is set with `2>/dev/null || true` in the shared modules, so it is a **no-op on bash 3.2** (macOS's system bash). Error propagation out of a command substitution differs between a maintainer's shell and CI. Do not rely on it; check the status explicitly.
  - Three different bash minimums by tree, and a construct is a portability break only below the one its own tree declares. `.github/scripts/` targets bash 3.2+. MCP servers and shared modules need 4.0+, from `${VAR^^}` in `config.sh`. `test-writing`'s server needs 4.4+: `mcp-server-test-rules/lib/common.sh` uses `declare -gA` (4.2) and `lib/get.sh` uses `local -` (4.4). `shopt -s inherit_errexit` sets no floor anywhere — every site writes it `2>/dev/null || true`, so it is a silent no-op below 4.4 rather than a requirement.
- `comments.preserve_patterns` = `# shellcheck disable=`, `# shellcheck source=`, `# bats file_tags=`, `# bats test_tags=`, `# type: ignore[`, `# noqa:`. Each reads as a comment and is tool input — deleting one changes lint, type-check, or test-filter behavior. Every ShellCheck disable in this repository is per-line and carries a trailing justification naming why the check does not apply (`# shellcheck disable=SC2034  # consumed by … via dynamic scope`); write a new one the same way and never widen one to file scope.
- `todo.ticket_format` = `TODO(#<issue>): <what is deferred, and the condition that clears it>`, with `FIXME` taking the same shape. The tracking reference is a GitHub issue number in this repository.

## Pre-Step-3

Before editing any file under `plugins/*/shared/` or `plugins/*/hooks/scripts/lib/`, read `templates/README.md` §How sync works and check whether the file is a template consumer. A consumer is a copy: edit `templates/<file>` instead and propagate to every consumer in the same change. Never edit a consumer in place — the template-sync check in `.github/workflows/validate.yml` fails the build, and a shared fix landed in one plugin only is a silent divergence in the others.
