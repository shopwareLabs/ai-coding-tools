# Changelog

## [1.0.0] - 2026-07-30

- Initial release with the `xml-config-migrating` skill: migrates extension XML configuration (service definitions, routes, package config) 1:1 to PHP configurators — package config to PHP or YAML — proves container and route equivalence via `debug:container` / `debug:router` dump diffs, runs the extension's tests, and reports the result in a fixed verification format.
- The dumps are taken by Claude as console commands, four per environment, with the environment selected by `--env=<env>` on the command line rather than an `APP_ENV` variable, which a docker, ddev, or vagrant wrapper shell drops. Each dump's output goes straight to a file under `var/xml-migration/`, so the bytes never enter the conversation.
- Three bundled scripts make the workflow machine-verified: `inventory.sh` (in-scope XML files with their type and environments), `verify-dumps.sh` (required-set check, kernel-environment identity check, dump normalization, before/after diff, inert classification, XML/PHP coexistence and leftover-reference checks, verification table), and `check-class-imports.sh` (missing `use` statements in migrated PHP). The verification table in the report is the script's output, not a hand-read diff.
- `inventory.sh` classifies a file whose basename and location match no rule by the Symfony namespace the file itself carries — DI documents become `services`, routing documents become `routes` — and skips an XML carrying neither with a stderr notice, so one foreign schema file no longer ends the scan and discards everything already classified.
- The skill names the one thing its instruments cannot check: a plugin's `packages/**` config is loaded by no bundle of the plugin's own, so the dump diff and the `FEATURE_ALL=major` gate see nothing whatever those files contain, and a packages row is reported as migrated with manual review rather than as verified.
- `verify-dumps.sh` holds each environment's parameter dumps to the environment their filename claims, so a set taken with `default` passed as a literal environment name can no longer certify a migration: that boots an environment nothing configures, and the dump records `kernel.environment` as `default` rather than the environment a request actually runs in.
